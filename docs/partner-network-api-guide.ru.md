# API поиска инфраструктуры для оценки подключения

Сервис принимает координаты здания и возвращает ближайшие кабели, узлы связи и муфты. Получите координаты во время геокодирования адреса на своей стороне. По результату можно оценить близость сети и передать инженеру подходящие точки для проверки трассы и свободной ёмкости.

## Доступ и первый запрос

Для подключения понадобятся адрес API и Bearer-токен с правом `network:nearby`. Токен закреплён за одной картой сети. Храните его на сервере интеграции и передавайте в заголовке `Authorization` по HTTPS.

`POST /api/network/nearby` принимает JSON. Подставьте выданный адрес API в `MAP_API_URL`, а токен передайте через переменную окружения `PARTNER_TOKEN`.

```sh
curl -sS -i "${MAP_API_URL}/api/network/nearby" \
  -H "Authorization: Bearer ${PARTNER_TOKEN}" \
  -H 'Content-Type: application/json' \
  --data '{"latitude":55.003,"longitude":37.003,"radiusM":300}'
```

| Поле | Значение |
| --- | --- |
| `latitude` | Широта в WGS 84, от −90 до 90 градусов. |
| `longitude` | Долгота в WGS 84, от −180 до 180 градусов. |
| `radiusM` | Радиус поиска в метрах. Укажите положительное число для поиска в радиусе или `0` для поиска ближайших объектов по всей карте. |

Все три поля обязательны. Передавайте значения числами JSON. Сервер выбирает карту по токену.

## Как читать ответ

Сначала проверьте HTTP-статус, затем `searchMode` в успешном ответе.

| `searchMode` | Результат |
| --- | --- |
| `within_radius` | В радиусе есть хотя бы один объект любого типа. Основные списки содержат объекты в радиусе, включая его границу. Список отдельного типа может быть пустым. |
| `nearest_outside_radius` | В радиусе пусто по всем типам. Основные списки содержат ближайшие объекты за его пределами. |
| `nearest` | В запросе указан `radiusM: 0`. Основные списки содержат ближайшие объекты со всей карты, включая объекты на нулевом расстоянии. |
| `empty` | В опубликованной версии карты нет объектов, доступных для поиска. Все списки пусты. |

Пример ответа `200 OK` для радиуса 300 м. В основных списках есть кабель и муфта. Ближайший узел находится за пределами радиуса и доступен в запасных вариантах.

```json
{
  "mapId": 3,
  "datasetVersion": "52fcd822-2828-4594-8cd6-32ed4f3710c9",
  "radiusM": 300,
  "searchMode": "within_radius",
  "cables": [{"objectId": "cable:10", "distanceM": 42.5}],
  "nodes": [],
  "couplers": [{
    "objectId": "node:2",
    "distanceM": 85,
    "connectedCables": [{"cableId": "cable:10"}]
  }],
  "alternatives": {
    "nodes": [{
      "objectId": "node:3",
      "distanceM": 310,
      "withinRadius": false,
      "connectedCables": []
    }],
    "couplers": [{
      "objectId": "node:4",
      "distanceM": 410,
      "withinRadius": false,
      "connectedCables": [{"cableId": "cable:27", "groupId": "cable_group:100"}]
    }]
  }
}
```

- **Основные списки** `cables`, `nodes` и `couplers` содержат до трёх объектов каждый, от ближайшего к дальнему. Тип точки определяйте по списку. Префикс `node:` используется и для узлов, и для муфт.
- **Запасные варианты** `alternatives.nodes` и `alternatives.couplers` содержат до двух дополнительных точек каждого типа без повторов из основных списков. `withinRadius` показывает, лежит ли точка в исходном радиусе. При `radiusM: 0` это поле равно `true` только для точки на нулевом расстоянии.
- **Связанные кабели** `connectedCables` есть у каждого узла и каждой муфты в обоих блоках. Список строится по учётным связям с концами кабелей. Он может включать кабели за пределами радиуса и кабели, которых нет в основном списке `cables`. У участка группы `cableId` обозначает сам участок, а `groupId` — кабельную группу. Отдельный кабель возвращается без `groupId`.
- **Расстояние** `distanceM` измеряется в метрах от координат заявки до точки узла или муфты, либо до ближайшей точки линии кабеля. Длину трассы до здания, стоимость работ и свободную ёмкость проверяет инженер.

`mapId` и `datasetVersion` показывают, по какой карте и версии данных выполнен поиск. Их можно сохранить вместе с результатом оценки заявки.

## Ошибки и повторные запросы

Ошибки приходят в JSON с полями `error.code` и `error.message`. Для автоматической обработки используйте HTTP-статус и код ошибки.

| HTTP | Код | Действие |
| --- | --- | --- |
| `401` | `AUTH_REQUIRED` | Проверьте заголовок `Authorization` и срок действия токена. |
| `403` | `ACCESS_DENIED` | Уточните у владельца API, выдано ли токену право `network:nearby` на нужную карту. |
| `422` | `INVALID_REQUEST` | Проверьте имена полей, числовой формат и диапазоны значений. |
| `503` | `NO_ACTIVE_DATASET` | Для карты ещё нет опубликованной версии. Сохраните заявку для повторной проверки. |
| `503` | `DATABASE_UNAVAILABLE` | Сохраните заявку и повторите запрос позже. |
| `500` | `INTERNAL_ERROR` | Если ошибка повторяется, сообщите владельцу API время запроса и код ошибки. |

`200` с режимом `empty` означает, что поиск выполнен по опубликованной версии. При `503` сервису следует сохранить заявку как ожидающую проверки.

Машиночитаемая схема запроса и ответа доступна по пути `/openapi.json` на сервере API.
