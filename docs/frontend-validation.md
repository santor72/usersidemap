# Проверка frontend

Дата: 2026-10-05. Проверки приложения выполнены на опубликованном снимке карты 3.

## Сборка и протокол

- Nuxt 4.5.2, MapLibre GL JS 6.12.0, Node 24 в Docker. Публичный runtime образ
  содержит только `.output`; внутренний адрес FastAPI остается server-only.
- `cd frontend && npm run test` — 18 тестов пройдены: максимум параллельных
  batch-запросов, устаревшее поколение, antimeridian/zoom, изоляция контроллеров,
  восстановление истекшего details lease, временный повтор без двойного прогресса,
  сохранение кандидатов после частичной ошибки, предел кэша по вершинам и обновление
  карточки после подтверждения выбранного объекта при движении, защита от запоздалых
  деталей другой selection, очистка после пустой выборки, ровно одна начальная загрузка при startup viewport event, сброс при смене API zoom/mapId
  и замена снимка без смешивания версий;
  преобразование backend-стилей проверяет fallback-иконку и сортировку по `zIndex`.
- `cd frontend && npm run typecheck` — успешно.
- `cd frontend && npm run build` — успешно, Nitro Node server preset. Vite выводит
  предупреждение о клиентском chunk MapLibre около 1.03 MB (279 KB gzip);
  MapLibre worker отдельно включен в Vite output (510.70 KB).
- `docker compose up -d --build --wait frontend` — API и
  frontend прошли healthcheck. Nitro передает запросы `/api/map` FastAPI.
- После регистрации фабрики `$createMapAdapter` в Nuxt-плагине контейнер
  пересобран; frontend healthcheck и API `/health/ready` прошли. `npm run
  typecheck`, `npm run test` (15 тестов) и `npm run build` успешны.
- Responsive resize проверен CDP на viewport 1100×800 и 760×700. При узком
  viewport панель переходит под карту, ширина карты и MapLibre canvas совпадают
  (744 px), высота canvas соответствует карте (259 px). Нажатие zoom-кнопки при
  узком viewport вызвало новый preload (6 → 7); `ResizeObserver` передает новый
  размер движку. Это проверка геометрии DOM/canvas; визуальная оценка качества
  рендеринга карты на мобильном размере остается отдельным пунктом.
- Стек проверен на macOS 27.0.1 / Apple M1 Max / 32 GB, Chrome 154, viewport
  1200×863; container runtime — Node 24.21.0. Пять серий по 10 drag-событий
  с интервалом 45 мс дали ровно один preload на серию. Каждая серия завершалась
  в состоянии ready с 19–33 объектами. `performance.memory.usedJSHeapSize`
  колебался от 59.7 до 64.4 MB без последовательного роста; это только оценка
  JS heap и не включает память WebGL/native.
- Шесть перемещений с паузой 260 мс создали шесть разных preload-запросов, как
  ожидается после debounce 180 мс; финальная область загрузила 17/17 объектов.
  Число query_leases в PostGIS изменилось с 223 (17 еще действовали) до 229 (23
  действовали). API TTL равен 600 секундам. Для работы добавлен исполняемый
  [`cleanup-map-leases.sh`](../deploy/cleanup-map-leases.sh) и пример запуска cron
  в backend README. Очистка на рабочей БД в этой проверке не запускалась.
- Серверная отмена проверена двумя preload запросами всей мировой области,
  прерванными клиентом через 10 мс (`AbortError`). Для контрольного повтора число
  leases было 239 всего / 10 действующих до и после; активных SQL запросов к
  карте после отмены не осталось. Незавершенная транзакция откатывает lease и
  подготовленные batch-записи. Успешно завершенные запросы оставляют leases до
  TTL; при перемещениях они накапливаются ожидаемо и удаляются плановой cleanup.
- API latency замерена отдельно от отображения в MapLibre. Для viewport 1200×863,
  Chrome 154, контейнеров Node 24 / FastAPI и пула из четырех параллельных batch
  запросов выполнено по три повтора. На малой области (46 объектов, 171 вершина,
  1 batch) медианы: preload manifest 9.5 ms, manifest→первый batch 5.8 ms,
  полный HTTP цикл 15.3 ms; перед этим холодный первый цикл занял 74.8 ms.
  На полной bbox карты при zoom 15 (7 386 объектов, 20 627 вершин, 74 batches,
  2.45 MB GeoJSON) медианы: manifest 780.4 ms, первый batch 13.3 ms,
  все batches 1 099.6 ms. Это HTTP/PostGIS время; время до первого отображения
  кадра и до settled idle MapLibre на этом объеме пока не измерено; оно измерено
  отдельно ниже для реального браузерного рендера.
- После изменения размеров точек Chrome 154 повторно проверил полную выборку в
  трех свежих page context (synthetic preload bbox по всей карте, zoom 15; камера
  оставалась в демонстрационной области). Каждый прогон принял 7 386 объектов /
  20 627 вершин в 74 batch без ошибок. Медианы: preload manifest 534.7 ms,
  manifest→первый UI-прогресс «1/74, 100/7386» 14.5 ms, manifest→UI `74/74`
  666.7 ms. JS heap в конце: 20.9 MB, прирост от начала preload 11.9 MB.
  Прогресс UI не замеряет завершение WebGL-отрисовки; позднее это проверено
  отдельным MapLibre idle benchmark. `performance.memory` не включает WebGL/native heap. Ошибок браузера не было.
- Параллельность batch-запросов сравнивалась на полной bbox (74 batches) при 1, 2,
  4 и 8 workers. Медиана полного HTTP цикла: 1091.6 ms (1, один прогон), 867.6 ms
  (2), 733.0 ms (4), 1105.7 ms (8; preload был медленнее). При 4 workers batch
  часть заняла 303–324 ms; при 8 batches закончились быстрее, но это не окупило
  более долгий preload. Оставлен текущий concurrency=4. Debounce 180 ms сохранен:
  пять серий быстрых движений с паузами 45 ms дали ровно один запрос на серию.
- `GET /health/ready` — PostGIS доступен. Каталог через frontend proxy отдает 3
  типа и 23 тематических слоя. Для тестовой области на zoom 15 preload вернул 24
  объекта всех трех типов в одной пачке; batch вернул 24 GeoJSON features.
  Запрос деталей вернул ту же queryId и datasetVersion.
- Esri imagery tile для начальной области отвечает `200 image/jpeg`; атрибуция
  передается в raster source карты.
- Chrome 154 после пересборки контейнера загрузил страницу и MapLibre worker
  (worker asset отдается с `/_nuxt` без ошибок загрузки); в `performance` нет
  ответов Nuxt assets со статусом 4xx/5xx. Ранее headful Chrome CDP подтвердил
  19 rendered cable features после запуска worker.
- После передачи `zIndex` в `circle-sort-key`/`symbol-sort-key` и fallback
  недоступных image-символов к встроенному треугольнику текущий Docker frontend
  перезагружен в Chrome CDP: 17/17 объектов загружены, `Runtime.exceptionThrown`
  и ошибки консоли отсутствовали. API-снимок карты 3 содержит 3 663 кабеля,
  1 289 узлов и 2 434 муфты; проверенная область стилей показала ширины кабелей
  1–5 px, узлы-треугольники с `zIndex=4` и муфты-круги с `zIndex=3`.

  объекта; canvas 738×776 совпал с контейнером карты, ошибок JS/консоли нет.

  штрихам, контурам и порядку «линии под узлами». Пиксельная выборка цвета круга

  раздувало штрихи в шесть раз. Адаптер теперь обновляет временную ширину свойства

  dash остаются заданными в пикселях. Для `cable:1393` пиксельные runs подсветки в
  MapLibre и Leaflet близки (различие границ штрихов 1–5 px из-за rasterization).

  `[37.598289,55.600926]` клик по этому dashed cable открыл карточку; закрытие
  карточки восстановило обычный цвет, ширину и шаг штрихов, console/runtime ошибок

Запуск: в отдельном терминале `cd frontend && NUXT_MAP_API_INTERNAL_URL=http://127.0.0.1:8006 npm run dev -- --port 3002`, затем headless Chrome с remote debugging (например `--remote-debugging-port=9231 --user-data-dir=/tmp/map-render-profile`) и `CDP_URL=http://localhost:9231 node scripts/benchmark-frontend-render.mjs`. Скрипт перехватывает batch-ответы и WebGL buffer/draw, слушает MapLibre `idle`, проверяет `areTilesLoaded`, `isSourceLoaded` и уникальные ID из `queryRenderedFeatures`, затем сохраняет кадр. `FULL_WORLD_PRELOAD=false` измеряет обычный начальный viewport.

Кадр: [`small-viewport-maplibre.png`](assets/small-viewport-maplibre.png).

В двух независимых dev-browser запусках первый `idle` с видимой геометрией после первого batch наступил через 34.3–35.1 мс и содержал 15 уникальных кабелей. Эти process-level значения включают Chrome allocation и служат агрегатной оценкой памяти карты/очередей при полном GeoJSON source, не точным счетчиком отдельных MapLibre/WebGL allocations. Карта в этих тестах держит все объекты в source, но рисует только текущую область.

- Эта проверка выявила потерю строкового ID при выдаче MapLibre rendered features:

  MapLibre корректно разбирал цвета/ширину из стилей и не подменял их fallback.
  Изменения источников между кадрами отправляются через MapLibre `updateData`;
  полный `setData` остается для reset.

  bbox `[37.655009,55.754985,37.672991,55.765114]` на zoom 15 и загрузил 46/46
  объектов (25 кабелей, 15 узлов, 6 муфт) одной пачкой.
- На этом viewport реальный клик открыл карточку кабеля `cable:79` с длиной 480 м,
  свойствами и двумя связями. Клики по узлу и муфте также открыли карточки с
  деталями; круговые и треугольные точечные слои присутствуют в карте.
- В браузере переключение в режим измерения и два клика дали линию 0.180 км и две
  точки без выбора сетевого объекта; zoom-кнопка отправила запрос с zoom 16, а
  сброс измерения вернул результат к 0 км/0 точек.
- Проверка обнаружила, что контейнер карты иногда ещё не был доступен через Vue
  template ref в callback старта. MapCanvas теперь ожидает следующий UI tick,
  использует DOM fallback и показывает ошибку инициализации вместо пустой карты.
- Каталог помечал default-visible только один тематический слой, который не содержал

- `npm audit --omit=dev --audit-level=high` — 0 уязвимостей в production-зависимостях.

## Импорт и ограничения приемки

Импорт карты 3 с политикой по умолчанию (`max-errors=0`) отказался публиковать
набор. В `sync_issues` изучены 163 объекта без пригодной геометрии:
84 узла без координат, 46 узлов с координатами за географическим диапазоном,
23 кабеля без координат и 10 вырожденных линий. Строгий запуск
`0dd26ed0-a557-4bd9-9d15-7fd824a4af7d` снова отказал; его наборы ошибок были

В одной странице создание → удаление → повторное создание карты дало 1 начальный preload и 1 preload после mount; сохраненная ссылка на старую карту имела `_removed=true`, новый instance отличался от старого, в DOM был один canvas. В интерфейсе приложения оставлены переключатели типов объектов; панель тематических
слоев убрана по требованию. Поддержка `layerIds` сохранена в `MapController` и
`MapDataClient`: при отсутствии тематического выбора в preload уходит `layerIds: []`,
то есть backend возвращает данные без фильтрации по тематическим слоям.

## Видимость типов кабеля

В актуальной конфигурации map API `MAP_API_VISIBLE_CABLE_TYPE_IDS=1`: импорт не
фильтрует строки типов, а слой `map_data.features` активного снимка сохраняет все
3 671 кабель. Из них 123 относятся к типам, отличным от 1, и остаются в snapshot;
каталог/preload карты возвращают только видимые кабели типа 1. В активном снимке
каталог API показывает 3 546 видимых кабелей типа 1 (два дополнительных объекта
типа 1 скрыты обычным флагом `hidden`). Проверено на работающем API: каталог и
preload используют allowlist. Интеграционный тест добавляет кабель типа 3, проверяет,
что он сохранен в published features, исключен из каталога и preload по умолчанию,
и возвращается при тестовой конфигурации `[1, 3]`.
