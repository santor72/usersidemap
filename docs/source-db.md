# Проверка исходной БД

Проверено 2026-10-03 через параметры US_DB_* из `.env`.
Использована транзакция только для чтения с ограничением времени запросов.
Значения подключения в отчет не включены.

## Подтверждено

- PostGIS источника: 2.5.4.
- Карта 3 имеет typemap = 3 (географическая карта).
- pbl_optica: 3704 записи, включая все типы и признаки видимости.
- pbl_uzel: 2513 муфт (тип 1), 1340 узлов связи (тип 4).
- Без coord: 33 муфты и 51 узел связи. Эти записи требуют проверки наследования.
- Среди всех непустых coord узлов: 4213 POINT и 23 POLYGON, SRID = 0.
- В таблице узлов есть также типы 2, 3, 5, 7, 8, 9.
- coord узла имеет тип geometry; coord кабеля и трассы имеют тип text.
- x1/y1 промежуточных точек имеют тип numeric.
- Для coord узла найден B-tree индекс; GiST-индекса этой колонки среди
  возвращенных индексов нет.

Количество записей источника не равно числу видимых объектов карты:
требуются фильтры, проверка координат и сборка маршрутов.

## Порядок осей

Сопоставлены 2266 начальных узлов и первых промежуточных точек кабелей.
При допуске 0.001 градуса 1500 совпали после перестановки осей, ни один
не совпал без перестановки. Это подтверждает соглашение legacy:
geometry узла хранит latitude,longitude, а x1/y1 точки longitude,latitude.

SRID 0 не определяет систему координат: перед назначением 4326 требуется
подтвердить соглашение источника. Схема нашей БД использует нормализованные
координаты longitude/latitude и пространственные индексы.

## Проверка синхронизатора 2026-10-04

Миграции применены к отдельному PostgreSQL 16 / PostGIS 3.5.
Интеграционные тесты на искусственных БД-источниках подтвердили повторное
применение миграций, согласованность снимка, запрет записи в источник,
сборку трех слоев, атомарную публикацию, удаление объектов через новый снимок,
сохранение предыдущей версии при сбое и удержание версий активными загрузками.
Все 31 тест прошли, включая гонку записи объекта с публикацией версии,
устраненную миграцией 003.

Первые попытки остановились на подключении (`ConnectionTimeout`). После
восстановления доступа выполнены три полных импорта источника: строгий,
с явно разрешенными пропусками в тестовой БД и повторный строгий.

Согласованный снимок включал 4375 узлов всех типов, 9880 зданий-зависимостей,
3704 кабеля, 9692 промежуточные точки и 111 промежуточных объектов.
Таблицы трасс и канализации в текущем источнике пусты; соответствующие ветви
сборки проверены модульными тестами, а не реальными трассами этой БД.

Строгий импорт обнаружил 163 ошибки и не опубликовал набор:

| Тип | Код | Количество |
| --- | --- | --- |
| Точки | missing_coordinate | 84 |
| Точки | invalid_coordinate | 46 |
| Кабели | missing_coordinate | 23 |
| Кабели | degenerate_line | 10 |

Все 46 недопустимых точек имеют долготу за пределами [-180,180] при
подтвержденном порядке осей. У 84 точек без координат наследование также
не дало координат; у семи из них есть ссылка на родительский узел.

Тестовый запуск с `--max-errors 163` опубликовал 7394 объекта за 33.86 секунды:
3671 кабель, 1289 узлов связи и 2434 муфты. Сохранены 23 тематических слоя,
448 принадлежностей и 7342 ссылки на концы кабелей. Из кабелей восемь скрыты,
девять планируются; эти признаки сохраняются для будущей фильтрации API.

Источники маршрутов: 2264 кабеля из заданных точек, 17 из промежуточных объектов,
1390 прямых. Геометрии валидны, непусты, имеют SRID 4326; всего 20730 вершин.
Staging успешного запуска удален. Повторный строгий импорт зарегистрирован
как failed, активная версия осталась прежней.

Проверки проводились только в отдельной тестовой целевой БД. Исходная БД
не изменялась. Нулевой допустимый порог остается значением по умолчанию;
тестовое разрешение 163 пропусков не является решением для рабочего запуска.

## Повтор проверки

Из корня проекта:

```sh
uv run --with 'psycopg[binary]' --with python-dotenv python scripts/inspect_source_db.py
```

Скрипт выводит метаданные и агрегированные количества; секреты не выводит.
US_DB_PORT необязателен, по умолчанию 5432.
