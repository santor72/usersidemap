# Расширение картографии frontend

Страница создает карту через клиентский `MapCanvas`, а `MapController`
связывает внедренные `MapDataClient` и `MapAdapter`. Приложение не импортирует
MapLibre и не формирует HTTP-запросы. Новый адаптер должен выполнять этот
контракт из `frontend/modules/cartography/runtime/core/contracts.ts`:

- сообщать viewport на начале и окончании движения;
- сообщать выбор и точки измерения;
- применять изменения `reset`, `add`, `update`, `remove` с поколением;
- поддерживать видимость типов, выбранный объект, режим, масштаб и освобождать
  все обработчики/ресурсы в `destroy()`.

Скелет находится в `frontend/modules/cartography/runtime/templates/MapAdapter.template.ts`.
Плагин `frontend/modules/cartography/runtime/plugin.ts` предоставляет точку
регистрации `$createMapAdapter(container, options)`; по умолчанию он лениво
создает MapLibre адаптер. `MapCanvas` управляет `ResizeObserver`, вызывает
`resize()` и освобождает контроллер и адаптер при размонтировании.

Загрузка управляется типами, переданными приложением в `MapControllerOptions`.
Поддержка геометрии относится к адаптеру; API-загрузка не зависит от движка.
MapLibre группирует объекты по типу и сохраняет feature ID между батчами.
Добавление нового типа требует API provider, сборки записи синхронизации,
записи в `frontend/app/map-types.ts` и визуального правила в адаптере.

MapDataClient и MapController не требуют DOM. Для проверок контроллера внедрите
тестовый адаптер с массивом изменений и вручную вызываемыми событиями.
Проверка в `frontend/tests/map-data-client.test.ts` запускает один контроллер
с двумя независимыми экземплярами тестового адаптера и подтверждает, что
загрузка типов, фильтры и инструменты не зависят от конкретного рендерера.
Экземпляры контроллера и клиента создаются отдельно для каждой карты.
