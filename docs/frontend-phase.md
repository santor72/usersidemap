# Следующий этап: модуль данных, картография и Nuxt-приложение

Обновлено 2026-10-05. Статус: согласованный план реализации с учетом принятого
[архитектурного ревью](frontend-architecture-review.md). Backend, Docker-стек и Nuxt frontend реализованы; критерии приемки пройдены,
измерения и ограничения зафиксированы в [плане](frontend-implementation-plan.md) и
[отчете проверки](frontend-validation.md).

## Результат и границы этапа

Простое Nuxt-приложение показывает кабели, узлы и муфты из FastAPI на карте
MapLibre с одной спутниковой подложкой Esri. Приложение определяет доступные
типы объектов и инструменты, размещает переключатели и карточку объекта.
Публичный интерфейс картографии скрывает библиотеку карты.

Сначала реализуется сквозной сценарий от каталога до деталей объекта.
После проверки загрузки, движения карты и инструментов из работающего адаптера
выделяется базовый шаблон для следующих картографических модулей. В этом этапе
достаточно небольших контрактов и композиции компонентов; универсальный
фреймворк плагинов и иерархия базовых классов не создаются.

## Компоненты и зависимости

```text
Nuxt-приложение: конфигурация, панели, карточка
                        |
                  MapController
                   /         \
          MapDataClient     MapLibreAdapter
               |                |
            FastAPI        карта, подложка,
                           взаимодействия
```

| Компонент | Ответственность |
| --- | --- |
| MapDataClient | Каталог, HTTP preload/batch/details, очередь запросов, поколения, версии, TTL, каноническое хранилище объектов, прогресс и изменения |
| MapController | Публичный интерфейс карты, конфигурация и выбранные фильтры, нормализация viewport, запуск/отмена загрузки, выбор объекта, координация инструментов |
| MapLibreAdapter | Создание карты, Esri, перевод стилей, применение изменений объектов, попадание по объекту, взаимодействия и ресурсы движка |
| Nuxt-интеграция | Регистрация компонентов, composables и настроек; клиентское создание карты и освобождение экземпляра |
| Frontend-приложение | Разрешенные возможности, начальное состояние, панели, переключатели, карточка, представление прогресса и ошибок |

MapController и MapLibreAdapter — внутренние части картографического модуля,
а не отдельные сетевые сервисы. Контроллер получает клиент данных и адаптер
через зависимости. Адаптер не вызывает API и не знает о queryId, preload или TTL.
MapDataClient не зависит от картографического движка.

Ядра загрузчика и контроллера — обычный TypeScript. Nuxt-интеграция остается
тонкой оболочкой. Каталог доступен через контроллер до создания WebGL-карты.
Публичные типы не содержат экземпляры MapLibre или события этой библиотеки.
Состояние создается на экземпляр карты. GeoJSON и объект движка не помещаются
в глубоко реактивное глобальное хранилище; UI получает небольшие снимки состояния.

## Конфигурация и публичный интерфейс

Различаются типы объектов, тематические группы Userside и внутренние слои
отрисовки. Прежнее неоднозначное поле `layers` заменяется на `objectTypes`.
Один тип объектов может отображаться несколькими слоями: геометрией, подписью,
выделением и областью попадания при клике.

Пример конфигурации приложения; initialCenter и initialZoom задаются приложением:

```ts
{
  mapId: 3,
  objectTypes: ['cable_line', 'node', 'coupler'],
  tools: ['select', 'measure', 'zoom'],
  basemap: 'esri-imagery',
  initialView: { center: initialCenter, zoom: initialZoom },
  initialState: {
    objectTypes: ['cable_line', 'node', 'coupler'],
    thematicLayerIds: [],
    activeTool: 'select'
  }
}
```

Верхние `objectTypes` и `tools` — разрешенный приложением набор.
`initialState` задает первоначально включенные типы, фильтры и активный режим;
далее это изменяемое состояние контроллера. Включенные типы всегда являются
подмножеством разрешенных и поддерживаемых. Неизвестная конфигурация возвращает
понятную ошибку. Ограничения UI не заменяют серверную авторизацию.

`thematicLayerIds` преобразуется клиентом данных в HTTP-поле `layerIds`.
Пустые `objectTypes` означают отсутствие объектов; пустые `thematicLayerIds`
означают все тематические группы, как в текущем API. Выключение всех
тематических переключателей нельзя трактовать как «ничего» при таком контракте.
В первом UI обязательны только переключатели типов объектов.

Начальная область задается как center/zoom или bounds (взаимоисключающие
варианты). Автоматическое определение области сети не предполагается:
текущий API не возвращает ее. Способ подключения Esri, URL, атрибуция и
параметры доступа хранятся в конфигурации зарегистрированной подложки.

Операции публичного интерфейса контроллера:

- Получение каталога, capabilities и текущего состояния, подписка на изменения.
- Создание карты в контейнере, изменение размера и уничтожение.
- Изменение включенных типов, тематических фильтров и области просмотра.
- Выбор/сброс объекта и получение его деталей.
- Выбор активного режима, команды масштаба, завершение/сброс измерения.
- Повтор текущей загрузки после ошибки.

События: `ready`, `catalogChanged`, `viewportChanged`, `objectSelected`,
`selectionCleared`, `loadingChanged`, `error`, `measurementChanged`.
`ready` означает готовность экземпляра карты к работе, а не завершение импорта
или загрузки всех объектов. Ошибки различают источник: данные, подложка,
движок, инструмент. События передают простые значения, ключи и координаты.
Изменение viewport через публичную команду и событие движка не должно
запускать два одинаковых запроса.

`select` и `measure` — взаимоисключающие режимы обработки клика; допустим
также неактивный режим. `zoom` — доступная команда, не активный режим.
Приложение размещает кнопки, модуль картографии реализует их действия.

## Каталог и расширение типов

`GET /api/map/layers?mapId=3` вызывается MapDataClient. Он возвращает каталог
контроллеру, который объединяет его с реестром типов, возможностями адаптера
и конфигурацией приложения. На этом основании frontend строит переключатели.
Каталог можно загрузить независимо от успешной загрузки спутниковых тайлов.

Backend сообщает о наличии данных: ID типов, счетчики, минимальный zoom,
тематические группы и datasetVersion. Названия типов для UI и метаданные
переключателей задаются клиентским реестром; у тематических групп названия
уже приходят из API. Отсутствующий в текущем каталоге тип не загружается,
неподдерживаемый адаптером отражается явно.

Для `cable_line`, `node`, `coupler` регистрируются описания/обработчики данных
и обработчики отображения. Общая HTTP-загрузка остается единой. Каждая
тематическая группа не требует собственного обработчика. Новый тип подключается
через реестры и поддержку backend без переписывания панелей и протокола батчей.
Если preload сообщает новую версию, каталог обновляется; он может измениться
между двумя HTTP-запросами и не считается гарантией версии следующего preload.

## Модуль данных и обновление выборки

Используется существующий [HTTP-контракт](map-api.md). Батч содержит GeoJSON
в `featureCollection`. Preload возвращает описание пачек без полного списка ID;
батчи не содержат min_zoom и тематических связей каждого объекта. Окончательную
принадлежность серверной выборке клиент устанавливает после получения всех батчей.

Контроллер преобразует viewport в bbox `[west, south, east, north]` и целый
zoom `floor(zoom)`, ограниченный диапазоном 0–24. Геометрия использует
`[longitude, latitude]`. Нормализуются долготы, широты, антимеридиан и обзор
шире полного мира; полный мир не превращается в bbox нулевой ширины.
Смена дробного zoom внутри одного целого значения сама по себе не требует
сброса по zoom, но изменение bbox учитывается.

При начале движения или изменении фильтров контроллер немедленно инвалидирует
текущий цикл через клиент данных. Клиент увеличивает поколение и отменяет
активные запросы. Новый preload запускается после завершения движения/короткой
задержки. Совпадающие нормализованные параметры объединяются. Отмена не должна
подавить необходимый повтор ранее отмененного незавершенного запроса.

### Правила переходов

| Изменение | Поведение |
| --- | --- |
| Перемещение, прежние фильтры и версия | Сохранить пересекающиеся объекты, подтверждать их поколением каждого нового батча; после полного успеха удалить неподтвержденные |
| Объект заведомо вне области | Удалить раньше; предварительная проверка может использовать оболочку геометрии, окончательный состав определяет сервер |
| Отключение типа | Сразу удалить его объекты и пересчитать запрос; оставшиеся типы могут сохраняться до подтверждения |
| Добавление типа | Запустить запрос с новым набором; сохранять объекты прежних типов при остальных равных условиях |
| Изменение целого API zoom или тематического фильтра | Сбросить выборку и загрузить заново: данных для точной локальной фильтрации недостаточно |
| Новая datasetVersion | Сохраненную старую версию обозначить как обновляемую; атомарно заменить первым принятым батчем новой версии, остальные отображать постепенно |
| Пустой успешный preload или ни одного включенного типа | Очистить объекты и выбор; для пустого набора типов сетевой запрос не нужен |
| Ошибка/отмена | Не выполнять завершающую очистку как при полном успехе; показать статус неполной загрузки или ошибки |
| Другая карта/источник | Полный сброс каталога, объектов, выбора и запросов; данные разных контекстов не переиспользуются |

При последовательных изменениях более строгий сброс имеет приоритет:
например, смена zoom не сохраняет старые объекты ради плавной смены версии.
Если первый батч новой версии не получен, сохраненная старая версия не становится
актуальной. После частичного получения новой версии отображается только она.
Любой готовый батч текущего поколения может начать новую версию; порядок
завершения HTTP-запросов не определяет правильность результата.

Объекты обновляются по стабильному ключу в контексте источника/карты;
`sourceKind:sourceId` из API сохраняется как ID feature в пределах экземпляра.
Каждое подтверждение относится к поколению и datasetVersion. Проверка поколения
выполняется перед изменением хранилища, отправкой событий и применением изменений
движком. Повтор батча не создает дублей и не увеличивает прогресс повторно.

Число параллельных батчей и попыток ограничено. Временные ошибки допускают
ограниченный повтор, постоянные ошибки и превышение лимитов требуют явной
реакции. Состояние сообщает фазу загрузки, прогресс, частичный результат и наличие
неподтвержденных объектов; частичный результат не выдается за готовую выборку.

История областей не накапливается. Заведомо вышедшие объекты удаляются при
обновлении области; консервативно сохраненные кандидаты удаляются после успешной
сверки. При незавершенных циклах применяется ограничение числа объектов/вершин
с явным сбросом устаревших кандидатов, чтобы постоянные перемещения и ошибки
не обходили предел памяти. Один тяжелый объект не обрезается молча.

Клиентская отмена не гарантирует отмену SQL-подготовки manifest. В приемку входят
проверка нагрузки после отмены и инструкция периодического запуска существующей
команды очистки leases. Таймер очистки не запускается в каждом API worker.

## Изменения объектов и отображение

MapDataClient владеет каноническими объектами, MapController передает адаптеру
изменения: добавление, обновление, удаление и полный сброс. Обновления содержат
контекст поколения; сброс версии и первый новый батч применяются согласованно.
Адаптер сериализует/объединяет обновления движка и не применяет запоздалую
очередь после сброса или уничтожения экземпляра.

Источники GeoJSON группируются по типам/задачам отрисовки. Один объект не создает
собственный source/layer, а каждый HTTP-батч не вызывает пересборку всей растущей
коллекции. Проверяется инкрементальное обновление MapLibre по стабильным ID на
закрепленной версии библиотеки. Прогресс получения данных и факт их отображения
различаются в измерениях; первый батч отображается до завершения полной загрузки.

Память приемки включает хранилище загрузчика, представления движка и ожидающую
очередь изменений. При удалении объекта освобождаются его представления;
уничтожение экземпляра отменяет запросы, очереди, подписки и WebGL-ресурсы.

## Выбор и детали объекта

Адаптер сообщает ключ выбранного объекта. Контроллер управляет выбором и через
MapDataClient получает детали; frontend отображает карточку через общий интерфейс.
Для деталей используется queryId, в котором объект подтвержден. До подтверждения
в текущем поколении карточка может показывать ожидание; устаревшая геометрия
не является основанием запросить детали в произвольном новом queryId.

После бездействия lease может истечь. Для `QUERY_EXPIRED`/`QUERY_NOT_FOUND`
допускается один автоматический цикл восстановления preload и повтор деталей
после подтверждения объекта. Постоянный таймер продления lease не нужен.
`OBJECT_NOT_FOUND` не трактуется как истечение, `BATCH_NOT_FOUND` не запускает
бесконечный новый preload. Если объект отсутствует в завершенной новой выборке,
его выбор и карточка сбрасываются с понятным состоянием для приложения.

Смена выбранного объекта, карты или версии инвалидирует предыдущие детали.
Даже успешно завершившийся старый ответ не заменяет текущую карточку.
Удаление выбранного объекта очищает выбор; при смене версии сохраненный ключ
можно выбрать повторно только после подтверждения новой геометрией и деталями.

## MapLibre, Esri и инструменты

MapLibre создается только на клиенте; Nuxt показывает placeholder до готовности.
Подложка — одна спутниковая Esri imagery. Перед подключением проверяются endpoint,
атрибуция и доступ; настройки размещаются отдельно от кода адаптера.
Ошибка тайлов не блокирует каталог или загрузку сетевых объектов.

Явный преобразователь переводит стили backend в оформление движка: цвета,
толщины, строковый dashArray, формы точек, порядок и выделение. Для еще не
перенесенных файловых иконок задается запасной символ. Визуальное соответствие
legacy проверяется на реальных кабелях, узлах и муфтах.

`select` выбирает объект; `measure` строит последовательность точек и считает
географическое расстояние, поддерживает завершение и сброс; `zoom` изменяет
масштаб через публичные команды. Общая логика режима/расчета по возможности
остается в контроллере/инструменте, адаптер преобразует действия движка и рисует
результат. Отключенный инструмент снимает свои обработчики. Клик в измерении
не должен одновременно выбрать сетевой объект.

## Nuxt-приложение, Docker и шаблон

Приложение получает данные о возможностях через контроллер и размещает панели,
переключатели типов, кнопки и карточку. Оно показывает загрузку, пустой результат,
неполные данные и ошибку с повтором. Прямых импортов MapLibre в приложении нет.

Nuxt добавляется в общий `compose.yml`; локально и на сервере используется
корневой `.env`. Браузер обращается к API через доступный ему URL; предпочтителен
единый origin с проксированием `/api/map` на FastAPI. Внутреннее Docker-имя API
не передается браузеру. Документация включает импорт, запуск и очистку leases.

Шаблон выделяется после рабочей реализации. Он содержит минимальный контракт
адаптера, заготовку, правила событий/ресурсов и пример регистрации обработчика.
Другой адаптер переиспользует контроллер и клиент данных. Второй полноценный
движок для приемки не нужен; независимость проверяется тестовым адаптером.

## Последовательность реализации

Подробный чек-лист работ, результатов и проверок по каждому шагу:
[frontend-implementation-plan.md](frontend-implementation-plan.md).
Таблица ниже группирует работы по архитектурным этапам; детальный план
разбивает их на 12 последовательных шагов.

| Шаг | Работа | Проверяемый результат |
| --- | --- | --- |
| 1. Контракты | Минимальные интерфейсы данных, контроллера, адаптера, конфигурации и изменений; границы TS-ядер и Nuxt | Тестовый адаптер подключается без MapLibre; понятны владельцы состояний |
| 2. Сквозной сценарий | Тонкое Nuxt-приложение, каталог, одна область, preload/batch, три типа, Esri, выбор и детали | Реальные объекты появляются по батчам; карточка работает через контроллер |
| 3. Корректность обновлений | Движение, нормализация viewport, фильтры, отмена, версии, ошибки, TTL, предел памяти | Быстрые изменения не дают дублей, старых ответов и неверного состава |
| 4. Инструменты и оформление | Измерение, масштаб, управление режимами, панели, перевод стилей | Все разрешенные инструменты работают, отключенные не реагируют |
| 5. Шаблон и упаковка | Выделить заготовку из проверенного адаптера; закончить Nuxt-интеграцию, Docker и инструкции | Новый обработчик подключается через реестр; общий стек запускает приложение |
| 6. Приемка и измерения | Реальный снимок, браузерные проверки, замеры и ограничения | Зафиксированы результаты, среда и известные ограничения |

Контракты уточняются по сквозному сценарию до оформления шаблона. Для реального
снимка используется постоянная целевая PostGIS; ошибки импорта анализируются,
допустимые пропуски не включаются автоматически.

## Критерии приемки

- Frontend управляет картой через единый интерфейс; адаптер не знает HTTP API,
  а загрузчик и контроллер проверяются без WebGL.
- Каталог, три типа, спутниковая Esri, стили и детали работают. Недоступность
  подложки и неподдерживаемый тип имеют отдельные состояния.
- Проверены быстрые bbox/zoom/фильтры, запоздалые ответы, отмена до нового preload,
  ограниченная очередь, повторы без дублей, пустая выборка и частичная ошибка.
- Проверены обновление datasetVersion до/между батчами, отказ первого батча,
  TTL при бездействии, отсутствие выбранного объекта и смена выбора во время деталей.
- Проверены линия с обоими концами вне bbox, антимеридиан, дробный zoom,
  обзор шире мира, полный сброс при смене карты и отсутствие двойных запросов.
- Измерение не конфликтует с выбором. Уничтожение и повторное открытие карты
  не оставляют подписок, запросов и объектов; экземпляры не разделяют состояние.
- Измерены время первой отрисовки и полной загрузки, отзывчивость и память после
  серии перемещений, число объектов/вершин и нагрузка после отмененных preload.
  Серверные замеры из map-api-benchmark.md не подменяют браузерные измерения.
- Выполнены проверки типов, сборка Nuxt, тесты переходов и браузерные сценарии.
  `docker compose up -d --build` запускает тот же стек локально и на сервере.

Собственное тайловое API объектов, дополнительные движки, расширение batch ради
локальной фильтрации и автоматическая область сети рассматриваются по результатам
измерений; они не являются обязательными работами этого этапа.
